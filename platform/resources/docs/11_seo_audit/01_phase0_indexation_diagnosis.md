# المرحلة 0 — تشخيص الفهرسة والاكتشاف

## النتيجة الأولى والأكثر أهمية

**البحث عن `site:qayd.accsystemerp.com` لا يُعيد أي نتيجة.**

هذا يعني أحد أمرين (أو كليهما):

1. الموقع غير مُفهرَس أصلاً في جوجل.
2. الموقع مُفهرَس بعدد ضئيل جداً من الصفحات لا يظهر في النتائج العامة.

في كلتا الحالتين، **يعاني قيد من مشكلة فهرسة، وليس فقط مشكلة ترتيب.**

الفرق جوهري: مشكلة الترتيب تعني "الموقع مفهرَس لكن في الصفحة الخامسة". مشكلة الفهرسة تعني "الموقع غير موجود في جوجل أصلاً".

---

## دليل 1 — غياب Sitemap.xml

**الحالة:** لا يوجد ملف `sitemap.xml` في الدومين.  
**الدليل:** البحث في الكود المصدري، `public/` directory، وملفات التوجيه لا يُظهر أي مولّد sitemap.  
**الخطورة:** حرجة  
**الثقة:** 100% (مؤكد من الكود المصدري)

**التأثير:** بدون sitemap، يعتمد Googlebot على:

- الروابط الخلفية للوصول إلى الموقع
- اكتشاف الصفحات عبر الـ crawl العشوائي

الموقع لديه 49+ صفحة توثيق + 10 صفحات تسويقية + صفحات قانونية = **~65 صفحة قابلة للفهرسة** لن يعرفها جوجل.

**الحل:** إضافة حزمة `spatie/laravel-sitemap` وتوليد sitemap ديناميكي يشمل كل المسارات العامة.

## دليل 2 — robots.txt مُسرِّف في الإذن، لكن غير مُفيد

**الحالة الحالية:**

```txt
User-agent: *
Disallow:
```

**التحليل:**

- السطر `Disallow:` (فارغ) يعني "لا تحجب شيئاً" — وهذا صحيح.
- لكن robots.txt المثالي يجب أن:
  1. يُشير إلى `sitemap.xml`
  2. يحجب صراحةً مسارات الـ admin والـ API

**الملاحظات الحرجة:**

- مسار `/admin/*` ليس محجوباً في robots.txt (رغم أنه محمي بـ middleware)
- مسار `/api/*` ليس محجوباً
- لا يوجد سطر `Sitemap: https://qayd.accsystemerp.com/sitemap.xml`

**robots.txt المثالي:**

```txt
User-agent: *
Disallow: /admin/
Disallow: /api/
Disallow: /login
Disallow: /logout
Disallow: /verify-email/
Disallow: /reset-password/

Sitemap: https://qayd.accsystemerp.com/sitemap.xml
```

**الخطورة:** متوسطة  
**الثقة:** 100%

## دليل 3 — تقنية SPA (Inertia.js) بدون SSR

**الحالة:** الموقع مبني بـ React + Inertia.js. الصفحات تُصيَّر عبر JavaScript في المتصفح.

**التحليل التقني:**

عندما يزور Googlebot الصفحة الرئيسية، يرى HTML أولياً كهذا:

```html
<div id="app" data-page='{"component":"Home","props":{"hero":null}}'></div>
```

ثم يحتاج لتنفيذ JavaScript لعرض المحتوى الفعلي.

**المشكلة:** Googlebot يُنفّذ JavaScript، لكن:

1. التنفيذ يحدث في وقت لاحق ("second wave crawl") — يتأخر التفهرس أسابيع
2. المحتوى الديناميكي المحمَّل من قاعدة البيانات قد لا يُعرَض بالكامل
3. ميزات التفاعل (hover، animations) لا تُنفَّذ

**الأكثر خطورة:** محتوى الصفحة الرئيسية يُحمَّل من `LandingPageContent` model في قاعدة البيانات. إذا تأخر تحميل هذا المحتوى، قد يُفهرَس Googlebot صفحة فارغة.

**الدليل:**

```tsx
// Home.tsx - المحتوى يأتي من props
const hero = props.hero; // قد يكون null
```

**الحل:**

- SSR كامل عبر `inertia-laravel` مع `@inertiajs/react` SSR adapter
- أو: تحويل الصفحات التسويقية إلى صفحات Blade ثابتة مع Vite

**الخطورة:** عالية  
**الثقة:** 95%

## دليل 4 — الدومين الفرعي وأثره على السلطة

**الدومين الحالي:** `qayd.accsystemerp.com`

**المشكلة الجذرية:**

- `accsystemerp.com` هو الدومين الرئيسي لشركة ACCSYSTEM
- الدومين الفرعي `qayd.` يُعامَل من جوجل كموقع **مستقل** بسلطة صفر
- كل روابط خلفية تذهب إلى `accsystemerp.com` لا تنتقل إلى `qayd.accsystemerp.com`

**مقارنة بالمنافسين:**

| المنافس | الدومين | سنوات الدومين (تقريبي) | مزايا |
| --- | --- | --- | --- |
| Wafeq | `wafeq.com` | ~6 سنوات | دومين مستقل، Series A $7.5M |
| Daftra | `daftra.com` | ~10 سنوات | دومين مستقل، محتوى ضخم |
| Ala-Hasba | `alahasba.com` | ~5 سنوات | دومين مستقل |
| **قيد** | `qayd.accsystemerp.com` | **غير معروف** | **دومين فرعي بلا سلطة** |

**التوصية:** الانتقال إلى دومين مستقل مثل `qayd.app` أو `qayd.io` أو `getqayd.com` كأولوية قصوى.

**الخطورة:** حرجة  
**الثقة:** 92%

## تصنيف نوع المشكلة

بناءً على الأدلة:

```txt
✗ مشكلة ترتيب (Ranking Problem)        — جزئياً
✓ مشكلة فهرسة (Indexation Problem)     — المشكلة الأساسية
✓ مشكلة قابلية الزحف (Crawlability)    — بسبب SPA
✗ مشكلة سلطة (Authority Problem)       — عامل مساهم
✓ مشكلة محتوى (Content Problem)        — عامل حرج
```

**الموقع لا يحتاج أولاً إلى تحسين ترتيبه — بل يحتاج إلى أن يكون موجوداً في جوجل.**
